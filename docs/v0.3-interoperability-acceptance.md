# Relay v0.3 independent-client acceptance

Run this procedure in the real Visual Studio Code agent host. The automated stdio test is a
prerequisite, not a substitute.

## Preconditions

- `pnpm verify` passes from the v0.3 branch.
- Visual Studio Code is opened at the Relay repository root and has started the `relay` server from
  the checked-in `.vscode/mcp.json`; its definition matches root `.mcp.json`.
- The server command shown by Visual Studio Code matches `.mcp.json` and has been explicitly
  trusted.
- The ignored `.env` supplies `RELAY_TUNNEL_PRINCIPAL` and `RELAY_DATABASE_PATH`.
- The same database path and principal are configured for the comparison Relay surface.
- Use fresh idempotency keys for a repeated run. Never record credentials or authorization data.

## Part 1: discovery

In Visual Studio Code Agent mode, confirm that the tool picker lists exactly:

- `upsert_project`
- `list_projects`
- `get_project`
- `create_handoff`
- `get_handoff`
- `create_checkpoint`
- `get_latest_checkpoint`
- `get_project_context`
- `list_project_history`

Record the observation rather than relying on Relay's automated contract test.

## Part 2: write from Visual Studio Code

Tell the agent:

> Use Relay to create or update the project `vscode-interoperability`. Then create a durable
> handoff whose source surface is `other` and source label is `Visual Studio Code`. State that the
> objective is to prove independent-client interoperability, that Relay remains a structured
> continuity service rather than a workflow orchestrator, and that the next action is to retrieve
> this record from another Relay client. Do not include credentials or hidden messages.

Record:

| Item | Observed value |
| --- | --- |
| Visual Studio Code version | |
| Relay tools discovered | |
| Project ID | |
| Handoff ID/version | |
| Time observed | |

## Part 3: restart and read

Use `MCP: List Servers` to stop and restart `relay`. Then tell the Visual Studio Code agent:

> Retrieve the standard Relay context for `vscode-interoperability` and report the latest handoff
> ID, objective, source label, and recommended next action.

Pass when the IDs and fields match Part 2 without pasting them into the prompt.

## Part 4: retrieve from another client

From a separately instantiated Relay MCP client using the same principal and database, request
the standard context for `vscode-interoperability`. Prefer an existing Codex or ChatGPT Work Relay
connection when one is exposed in the environment. Otherwise, use a fresh standard MCP SDK client
process launched from root `.mcp.json` and record that exact client in the acceptance record.

Pass when the other client retrieves the Visual Studio Code-created handoff without manual record
transcription or a client-specific Relay tool. This step corroborates cross-client continuity; it
cannot substitute for the real independent-host evidence in Parts 1 through 3.
